# FONG 需求文档 v1（针对 0.4.75 – 0.5.0）

日期：2026-11-08　适用：Windows 客户端 + 手机网页版 /m/ + 服务端
原则：**先稳，再全，最后好看。** 5 个真实用户，任何需求都不能以"引入新故障"为代价（约束见 02 架构 §6）。

所有判据的测量方法、字段和阈值见 04 验收报告，编号一一对应（R1 ↔ A1）。

## 2. 音频质量（P0）

### R1　长时间通话无咔哒、无电音
- **场景：** 两人通话 60 分钟，期间一方开一款 3A 游戏或浏览器开 20 个标签页。
- **用户感知：** 全程不出现"啪"一声、"滋"一段的声音；不需要重启软件。
- **判据：** 60 分钟内咔哒事件 ≤ 2 次；饥饿持续 > 50 ms 的事件 ≤ 5 次；无需重启。
- **不做：** 不要求降噪在抢占期间仍然生效（抢占期间直通原声是可接受的）。

### R2　切换降噪档位无感
- **场景：** 通话中在 关/低占用/质量/自然 之间连续切换 20 次。
- **判据：** 每次切换从点击到新档生效 ≤ 200 ms；切换期间对端收到的音频无断流（RTP 间隔 ≤ 60 ms）；无咔哒；不触发重连；UI 显示的档位与 native 实际档位 20/20 一致。

### R3　网络一般时不卡顿
- **场景：** 上行带宽 2 Mbps、丢包 3%、抖动 30 ms（家用 Wi-Fi 典型值）。
- **判据：** 对端播放端 `concealedSamples / totalSamples` ≤ 2%；端到端延迟 ≤ 250 ms；不触发自动重连。
- **附带要求：** Opus 默认码率改为语音合理值（建议 48 kbps，用户可在设置里选更高），默认 ptime 20 ms，开启 FEC 与 VBR。高码率作为"音乐模式"保留。

### R4　无可察觉回声
- **场景 a：** 双方戴耳机，系统音量 50%。**场景 b：** 一方用外放，对方戴耳机。
- **判据：** 场景 a 回声回传电平 ≤ -45 dBFS（基本不可闻）；场景 b ≤ -30 dBFS，且 AEC 收敛 ≤ 2 秒；far 参考与 near 的对齐偏差在 60 分钟内不漂移超过 ±20 ms。
- **备注：** 场景 a 戴耳机还有回声，通常不是算法问题，而是参考信号错位或耳机漏音被高灵敏麦克风收进去，因此 far/near 对齐是首要修复项（0.4.75 已做）。

### R5　低配机可用
- **基准机：** 4 核 4 线程、8 GB 内存（如 i5-6500 / R3 3200G 一档）。
- **判据：** 质量档下降噪处理单块耗时 p99 ≤ 7 ms；超过阈值 2 秒内自动降到低占用档并提示"已为保证流畅降到低占用档"；整个客户端 CPU 占用 ≤ 15%。
- **不做：** 不要求低配机强制跑满质量档。

## 3. 可观测性（P0）

### R6　问题可事后定位
- **场景：** 用户说"昨晚 9 点多开始卡"。
- **判据：** 开发者拿到用户一键导出的诊断包后，10 分钟内能分辨是 CPU、网络、编码还是设备原因；日志每天 ≤ 600 KB；导出诊断不需要用户打开开发者工具。
- **字段与频率：** 见 00 文档 Q6 与 04 验收 A6。

## 4. 语音连麦基础功能（P1–P2）

现状盘点（代码里已经有的，不重复做，只补"稳"和"看得见"）：

| 功能 | 现状 | 本期要求 |
|---|---|---|
| 闭麦 / 闭听 | 有 | 全局快捷键在游戏全屏下 10/10 生效 |
| 按键说话 | 有（uiohook） | 按下到出声 ≤ 100 ms；松开尾音保留 200 ms 不切字 |
| 单人音量 | 有 | 0–200%，重进频道后保持 |
| 输入/输出设备选择 | 有，拔出回落默认 | 插入新耳机提示"是否切换"；切设备不重建降噪链 |
| 说话指示 | 有 | 延迟 ≤ 150 ms，静音时不闪 |
| 断线重连 | 有（退避重试） | 见 R9 |
| 麦克风试听 | **无** | R7 |
| 网络质量显示 | **无常驻显示** | R8 |
| 诊断导出 | **无** | R6 |
| TURN / TCP 兜底 | **无** | R10 |

### R7　麦克风试听（P1）
设置页"试听"按钮：经过当前降噪档位后回放给自己，延迟可见（显示 ms）。用于用户自查"是我麦的问题还是网络的问题"。
- 判据：开启后 1 秒内听到自己；关闭后不残留音频节点（节点数回到开启前）。

### R8　网络与音频状态可见（P1）
每个人名旁一个信号格：绿 / 黄 / 红，悬停显示 RTT、丢包、抖动缓冲、对方降噪档。
- 判据：阈值 绿 RTT < 100 ms 且丢包 < 1%；黄 < 250 ms 或 < 5%；其余红。每 2 秒刷新。

### R9　断线重连可预期（P1）
- 判据：网络断开 10 秒后恢复，30 秒内自动回到原频道且双方能互相听到；重连期间横幅显示原因与倒计时；连续失败 5 次后停止并给出"可能是 UDP 被封，试试开启 TCP 兜底"。

### R10　受限网络能连上（P2）
服务端提供 TURN over TCP/TLS 443 兜底（coturn 或 pion/turn，与 SFU 同机）。
- 判据：只放行 TCP 443 的网络下能进频道并通话；直连可用时不走中继（中继流量 < 5%）。

### R11　手机网页版 /m/ 不退化（P0，约束）
任何改动后 /m/ 在 iOS Safari 和安卓 Chrome 上进频道、说话、听到对方 3/3 通过。

### R12　版本与更新（P2）
设置页显示客户端版本、native 版本、模型版本；有新版时提示，不强制。避免"测的是旧二进制"（历史教训 1）。
