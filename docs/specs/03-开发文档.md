## 1. 模块职责

| 模块 | 文件 | 职责 | 不负责 |
|---|---|---|---|
| 采集/回放调度 | denoise-worklet.js | 128 样本回调与 480 块之间的缓冲；饥饿兜底；延迟调速 | 任何 DSP |
| 处理调度 | denoise-worker.js | 等输入块、调用 native、写输出环；far 对齐；统计 | UI、重连 |
| DSP | rust/dsp、rust/native | AEC、降噪四档、啸叫、瞬态 | 线程调度（0.4.8x 前） |
| 音频编排 | renderer.js `Mic`、`Denoise` | 建链、切档、守护 | DSP 细节 |
| 通话 | renderer.js `Call` | 信令、PeerConnection、重连、getStats | 音频处理 |
| 主进程 | main.js | 热键、托盘、更新、**日志落盘（新增）** | 音频 |
| 服务端 | server/*.go | 鉴权、空间/频道、SFU 转发 | 音频内容 |

## 2. 数据流（一块 10 ms 音频的一生）

1. worklet 每 128 样本回调，写入输入环；凑满 480 → `inWrite++` → `Atomics.notify`。
2. worker 醒来：读控制槽 → 取 far 块（与 near 1:1）→ `native.process()` → 写输出环 `outWrite++`。
   - 输入积压 > `MAXLAG`：丢中间块，**far 同步丢同样块数**。
   - 输出环满：丢这块输入，far 同步丢 1 块。
3. worklet 读输出环：有数据就按样本播放；水位过高由调速器跳块；没数据走饥饿直通。
4. worklet 输出进 MediaStreamDestination → Opus 编码 → SFU 转发。

## 3. 改动清单（按执行顺序）

### 步 1　日志与诊断导出（R6）
- **新增** `client/diag-log.js`（渲染进程）：每 10 秒从 SAB 统计槽和 `pc.getStats()` 汇总一行；事件接口 `diag.event(name, data)`。
- **main.js**：IPC `diag:append` 写 `app.getPath('userData')/logs/fong-YYYYMMDD.jsonl`；单文件 1 MB 截断；启动时删 7 天前文件；`diag:export` 打包最近 3 天为 zip 放到桌面。
- **preload.js**：暴露 `diag.append`、`diag.export`。
- **renderer.js**：在饥饿进入/退出、硬丢、切档、旁路、重连、设备变化、ICE 状态 7 处调用 `diag.event`。worklet 侧把饥饿进入/退出次数写进新的 SAB 计数槽（不在音频线程里 postMessage）。
- **风险：** 写盘在主进程，异步追加，对音频线程零影响。
- **回滚：** 不加载 `diag-log.js` 即可，其他代码只调用一个可空对象。

### 步 2　0.4.75 音频链路（R1、R4）—— 已完成，PR #1
- worklet：饥饿直通 + 2 ms 淡化；延迟调速器（水位 > prefill+2 且安静块 < -50 dBFS 跳一块，> prefill+5 无条件跳，接缝 2 ms 交叉淡化）；诊断槽只在 `diag` 开时读。
- worker：`MAXLAG` 3→6；`skipFar(n)` 与 near 丢块数一致；far 积压 > 6 重同步到 2；新增 `farLag`、`farResyncs`。
- **风险：** 最大延迟 37→68 ms（仿真），平均 +约 10 ms。若用户感觉延迟变大，先把 `MAXLAG` 调回 4 观察。
- **回滚：** revert 两个文件。

### 步 3　Opus 默认值（R3）
- `renderer.js`：新增 `OPUS_TIERS = [32, 48, 64, 96, 128]`，默认 48；`cbr: '0'`；ptime 10→20；`useinbandfec: '1'` 保留。已有用户设置值 > 128 的迁移为 128，并在设置页加"音乐模式（高码率）"开关恢复 256。
- **风险：** 已存设置迁移。迁移只在版本号首次升级时执行一次，记 `event:settings_migrate`。
- **回滚：** 常量改回。

### 步 4　切档热切（R2）
- `renderer.js`：档位按钮只调用 `Denoise.setMode(m)`（写 `C_CMD_MODE`），不再调 `Mic.start()`；之后显式调用 `_startDenoiseGuard()` 重置基线（替代原来依赖重建的副作用，见 1338 行注释）。
- `rust/native set_mode()`：新引擎预热一块；下一块新旧引擎都算，480 样本线性交叉淡化；之后释放旧引擎。各档延迟用延迟线对齐到 544 样本。
- UI 档位从 native `get_mode()` 读回显示。
- **开关：** 设置项 `hotSwitch`，默认开；关掉回到原重建路径。
- **风险：** 交叉淡化那一块 CPU 翻倍（GTCRN 约 +2 ms）。低配机由步 5 兜底。

### 步 5　CPU 守护自动降档（R5）
- worker 每块记 `process()` 耗时，滑动 2 秒；均值 > 7 ms 或 p99 > 9 ms → 写 `C_REQ_DOWNGRADE` 槽；renderer 收到后切到低占用档并横幅提示。
- `dropped` 接入守护：按 1 秒窗口增速判定（> 5 块/秒持续 3 秒视为异常），不看累计值。
- **回滚：** 开关 `autoDowngrade`。

### 步 6　native 推理线程 + 16k 分带降噪（R5）
- native 内起专用线程，Windows 下 `AvSetMmThreadCharacteristicsW("Pro Audio")`；worker 只做 SAB 搬运。
- `gtcrn48.rs::run_onnx`：IoBinding 绑定预分配输出，state 双缓冲交换，消除每帧约 80 次小分配（27 次输入名 clone、26 次 `format!`）。
- 质量档换 16k GTCRN：48k→16k 降采样算增益，增益插值回 48k 施加于原信号，8 kHz 以上直通。
- **回滚：** 档位映射回 48k 模型；线程开关回到 worker 同步调用。

### 步 7　基础功能（R7–R12）
- renderer.js 先拆模块再加功能：`audio/`（Mic、Denoise、守护）、`call/`（信令、PC、重连、统计）、`ui/`。**拆分本身单独一版，行为零变化**，用 04 的回归清单验收后再加功能。
- 试听（R7）、信号格（R8）、重连提示与 TCP 建议（R9）、TURN（R10，服务端加 pion/turn 监听 TCP 443）、版本显示（R12）。

## 4. 风险登记

| 风险 | 触发 | 缓解 |
|---|---|---|
| 调速器跳块切掉字头 | 说话起音正好落在水位高时 | 只在安静块跳；硬跳阈值 prefill+5 才触发 |
| 迁移 Opus 设置惹怒音乐用户 | 有人在放歌 | 音乐模式开关一键恢复 |
| 热切漏掉守护复位 | 有人日后改切档路径 | 守护复位改成显式调用 + 单元测试覆盖 |
| native 线程与 SAB 竞争 | 步 6 | SAB 接口不变，先在 bench 下压测 30 分钟 |
| /m/ 被服务端改动影响 | 步 7 TURN | /m/ 三端回归列入每版验收 |

## 5. 分支与发版

- `main` 只收验收通过的版本；每步一个 `fix/` 或 `feat/` 分支，草稿 PR，验收记录贴进 PR。
- tag 规则 `v0.4.75`；发版附带三项版本号。
- 离线仿真：`SIG=speech node tools/sim_worklet.mjs <worklet路径> <MAXLAG> <mirrorFar> <分钟> <seed>`，任何动 worklet/worker 的 PR 必须贴原版与新版两组结果。
