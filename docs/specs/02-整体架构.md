# FONG 整体架构（0.4.74 现状 → 0.5.0 目标）

日期：2026-11-08

---

## 1. 部署拓扑

```
 Windows 客户端 (Electron)          手机浏览器 /m/
        │  HTTPS / WSS                    │
        │  WebRTC UDP 20000–39999         │
        ▼                                 ▼
 ┌──────────────── 单台 VPS ────────────────┐
 │  Go 进程（一个二进制）                    │
 │   ├ HTTP API  api.go（空间/频道/封禁/密码/上传）│
 │   ├ 鉴权      auth/ authcode/（设备密钥、邮箱验证码）│
 │   ├ 管理后台  admin.go（/api/admin/stats）      │
 │   ├ SFU       peer.go（pion/webrtc v4，只转发不混音）│
 │   └ 静态文件  /m/、客户端下载                  │
 │  存储：/var/lib/fong/fong.json（临时文件+rename 原子写）│
 │        data/img、data/file（相对工作目录）       │
 └──────────────────────────────────────────┘
```

- **无 TURN、无 TCP 媒体兜底**：UDP 被封的网络进不了频道。
- **SFU 只转发**：服务端 CPU 与人数线性相关，5 人规模余量充足；服务端不碰音频内容，所以所有音质问题都在客户端。

## 2. 客户端进程与线程

```
主进程 main.js ── 托盘、更新下载、全局热键（uiohook）、设置持久化
   │ preload.js（contextBridge：native、热键、更新）
渲染进程 renderer.js（4,904 行，UI + 通话 + 音频编排全在一个文件）
   ├ 发送链：getUserMedia(echoCancellation:false)
   │        → AudioWorklet denoise-worklet.js（攒 480 块）
   │        → SAB 输入环 ─Atomics.notify→ Worker denoise-worker.js
   │        → fong_native.node（Rust dsp：AEC / RNNoise / GTCRN / 啸叫 / 瞬态）
   │        → SAB 输出环 → worklet 取块 → MediaStreamDestination → RTCPeerConnection
   ├ 参考链：<audio>.captureStream() → aec-ref-worklet.js → SAB far 环 → worker
   ├ 收听：  RTCPeerConnection → <audio>（setSinkId）
   └ VAD：   vad-gate.js / vad-gate-worklet.js（说话指示）
```

控制面：SAB 原子槽（`C_CMD_MODE / ENABLE / TILT / HOWL / TRANS / RESET`），worker 每块轮询一次。

## 3. 关键参数（代码事实）

| 项 | 值 | 位置 |
|---|---|---|
| 采样率 / 块长 | 48 kHz / 480（10 ms） | worklet、worker |
| 输出环 | 12 块（120 ms） | `OUT_SLOTS` |
| worker 追帧阈值 | 0.4.74：3 块；0.4.75：6 块 | `MAXLAG` |
| far 环 | 16 块；0.4.75 起积压钉在 2 块 | `FAR_SLOTS / FAR_TARGET` |
| 降噪档 | 0 关、1 RNNoise、2 GTCRN-48k、3 高通+自适应门（默认） | native `set_mode` |
| GTCRN 延迟 / RTF | 544 样本（≈11 ms）/ ≈0.19 | gtcrn48.rs |
| Opus | 默认 256 kbps、CBR、FEC、ptime 10 ms、单声道 | renderer.js 10–28、926 |
| 接收抖动缓冲目标 | 60 ms | `JITTER_TARGET_MS` |
| 重连退避 | 1、2、4、8、15、15… 秒 | renderer.js 1739 |

## 4. 瓶颈与风险（按影响排序）

1. **实时音频跑在不可控优先级上。** 推理在 JS Worker 里同步调用 native，Worker 线程无法设实时优先级；游戏/杀毒一抢就停顿。0.4.74 对停顿的两层兜底（硬丢、循环旧块）都是硬切，直接变成咔哒和电音。
2. **48 kHz 全带推理。** 质量档推理量是 16 kHz 方案的 3 倍，低配机余量不够。
3. **发送码率过高。** 256 kbps CBR + 10 ms 包，对上行抖动最敏感的组合。
4. **renderer.js 单文件 4,904 行。** UI、信令、音频编排、守护逻辑交织，"改一处坏一处"的结构性原因；`_startDenoiseGuard` 这种"依赖另一处副作用"的隐式耦合是典型。
5. **零持久化日志。** 时间相关的问题无法复盘，修复只能靠猜，导致历史上"验证付给错的对象"。
6. **无 TURN。** 受限网络直接失败，且失败原因对用户不可见。

## 5. 演进方向（不重构媒体层的前提下）

| 阶段 | 改什么 | 不改什么 |
|---|---|---|
| 0.4.75 | worklet/worker 平滑兜底、far/near 对齐、日志 | 链路拓扑、native |
| 0.4.76 | Opus 默认值、切档热切、CPU 守护降档 | 链路拓扑 |
| 0.4.8x | native 推理线程（MMCSS "Pro Audio"）、GTCRN IoBinding 去分配、16k 分带降噪 | SAB 接口保持不变，worker 退化为转发 |
| 0.5.0 | renderer.js 拆为 `audio/`、`call/`、`ui/` 三个模块；TURN；试听；网络状态 | 产品形态 |

**架构边界：** SAB 环 + 原子槽这套接口保留，作为 JS 与 native 之间唯一的契约；所有优化都在接口两侧各自完成，任何一步都能单独回滚。

## 6. 硬约束

1. 5 个真实用户，不为性能重构整个媒体层。
2. 改动必须可局部回滚（开关或单文件 revert）。
3. 单台 VPS，无额外预算。
4. 不采购商业 RTC。
5. 用户多为普通配置机器。
6. /m/ 手机网页版必须继续可用（/m/ 不走 native 降噪链，音频改动不影响它，但 SFU/信令改动会）。

## 7. 与 KOOK 的结构对照

| 维度 | KOOK 0.112 | FONG 0.4.74 | 结论 |
|---|---|---|---|
| 传输 | 声网 SDK | 自建 pion SFU | 保持，约束 4 |
| 降噪采样率 | 16 kHz | 48 kHz | 质量档迁移 16k 分带（阶段 0.4.8x） |
| 帧长 | 128 | 480 | 保持 480，见 00 文档 Q2 |
| 饥饿 | 直通 | 循环旧块 | 0.4.75 改直通 + 淡化 |
| 切档 | 热重启清历史 | 重建整条链 | 0.4.76 改热切 + 交叉淡化 |
| 看门狗 | 落后 >2× 即 reset，>5% 上报 | 只看 underruns，`dropped` 不参与 | 0.4.76 改按 1 秒窗口增速 |
