## 2. 客户端

```
主进程 main.js ─ 托盘、更新、全局热键（uiohook）、设置
  │ preload.js（contextBridge）
渲染进程 renderer.js（4,904 行）
  ├ 发送链  getUserMedia(echoCancellation:false)
  │        → denoise-worklet.js（128→480 攒块，饥饿兜底）
  │        → SAB 输入环 → denoise-worker.js（Atomics.wait）
  │        → fong_native.node（AEC / RNNoise / GTCRN / 啸叫 / 瞬态）
  │        → SAB 输出环 → worklet → MediaStreamDestination → Opus → PC
  ├ 参考链  <audio>.captureStream()（key 'cap:<mid>'，syncCapStreams 管理）
  │        → aec-ref-worklet.js → SAB far 环 → worker
  │        看门狗 AecRef.watch()：1 秒一查，写指针 3 秒不动 → resync；累计 4 次 → 重建
  ├ 守护    _startDenoiseGuard：underruns 触发旁路（dropped 不参与）
  ├ 收听    PC → <audio>（setSinkId），jitterBufferTarget 60 ms
  └ 重连    1、2、4、8、15 秒退避；RTP 停滞两次后停止
```

### 2.1 关键参数

| 项 | 值 |
|---|---|
| 采样率 / 块 | 48 kHz / 480（10 ms） |
| 输出环 / far 环 | 12 块 / 16 块 |
| worker 追帧 `MAXLAG` | 3（0.4.75 草案 6） |
| 饥饿策略 | 0.4.74：播一次 + 线性渐隐；0.4.75 草案：直通 + 2 ms 淡化 |
| 降噪档 | 0 关、1 RNNoise、2 GTCRN-48k（RTF≈0.19，延迟 544 样本）、3 高通+自适应门（默认） |
| Opus | 256 kbps、CBR、ptime 10、FEC、单声道 |

## 3. 瓶颈（按 0.4.74 长跑数据重排）

1. **自愈逻辑本身是故障源。** 0.4.74 前每分钟级重建整条链；0.4.74 后因 `_heals` 不清零，改为小时级重建。分级自愈是首要结构改动（00 文档 Q1）。
2. **实时音频跑在不可控优先级上。** 推理在 JS Worker 里同步调 native，无法提优先级；游戏抢核时饥饿。仿真：0.4.74 饥饿策略仍产生咔哒（10 分钟 94 次）。
3. **零持久化日志。** 周期性问题只能靠现场复现；历史上 5 次以上"验证付给错的对象"。
4. **48 kHz 全带推理。** 低配机余量不足。
5. **发送码率过高。** 256k CBR + 10 ms 包。
6. **renderer.js 单文件 4,904 行。** 守护依赖重建副作用这类隐式耦合是"改一处坏一处"的结构原因（0.4.74 修的 4 个根因里 2 个是 0.4.73 引入的）。
7. **服务器未知。** 可能是瓶颈，也可能不是，R13 回答。
8. **无 TURN。** 受限网络失败。

## 4. 演进（不重构媒体层）

| 版本 | 内容 | 边界 |
|---|---|---|
| 0.4.75 | 日志；看门狗分级 + `_heals` 清零；饥饿直通 + 调速器 + far 1:1 | 不动 native、不动拓扑 |
| 0.4.76 | Opus 默认值；切档热切；CPU 守护降档 | native 只改 `set_mode` |
| 0.4.8x | native 推理线程（MMCSS "Pro Audio"）；GTCRN IoBinding；16k 分带 | SAB 接口不变 |
| 0.5.0 | renderer.js 拆 `audio/ call/ ui/`；TURN；试听；信号格 | 产品形态不变 |

**唯一契约：** SAB 环 + 原子槽。两侧各自演进，任何一步可单独回滚。

## 5. 与 KOOK 0.112 对照

| 维度 | KOOK | FONG 0.4.74 | 去向 |
|---|---|---|---|
| 传输 | 声网 | pion SFU | 保持 |
| 降噪采样率 | 16k | 48k | 质量档 16k 分带 |
| 帧长 | 128 | 480 | 保持 |
| 饥饿 | 直通 | 播一次+渐隐 | 直通 + 淡化 |
| 切档 | Hotrestart，不重建 | 重建整条链 | 热切 + 交叉淡化 |
| 看门狗 | 落后 >2× reset 处理器，>5% 上报 | 累计 4 次重建整链 | 分级，只动最小单元 |

## 7. 硬约束
1. 5 个真实用户，不为性能重构媒体层。
2. 历史回归频发，改动必须可局部回滚。
3. 单台 VPS，无额外预算。
4. 不采购商业 RTC。
5. 用户多为普通配置。
6. /m/ 必须继续可用。
7. 每项改动独立回滚。
